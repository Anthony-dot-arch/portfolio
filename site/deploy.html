Infrastructure as Code

How this site is built and deployed

No clicking in the portal. The Azure infrastructure is defined in Terraform, and every push to GitHub deploys the site automatically.

Architecture

Two flows: Terraform creates the infrastructure once, GitHub Actions deploys the content on every push.

The Terraform code

The whole infrastructure fits in a few lines. Changes are reviewed with terraform plan before they're applied.

resource "azurerm_storage_account" "site" {
  name                       = "anthonyportfolio${random_string.suffix.result}"
  resource_group_name        = azurerm_resource_group.portfolio.name
  location                   = "francecentral"
  account_tier               = "Standard"
  account_replication_type   = "LRS"
  https_traffic_only_enabled = true
  min_tls_version            = "TLS1_2"
}

resource "azurerm_storage_account_static_website" "site" {
  storage_account_id = azurerm_storage_account.site.id
  index_document     = "index.html"
  error_404_document = "index.html"
}

Design choices

Cheap and controlled

Standard LRS storage costs a few cents per month for a small site. A Cost Management budget alert acts as a safety net.

Secrets stay out of Git

The storage connection string is stored as a GitHub Actions secret, never in the repository. Terraform state files are git-ignored.

Reproducible

Delete the resource group and run terraform apply: the same infrastructure comes back in minutes.

Deployment flow

  1. terraform apply creates the resource group and a storage account with static website hosting enabled.
  2. The storage connection string is read with terraform output and saved as a GitHub secret.
  3. Every push to main triggers the GitHub Actions workflow.
  4. The workflow uploads the site/ folder to the $web container with Azure CLI. The new version is live in about a minute.
