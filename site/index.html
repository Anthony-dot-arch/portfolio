Restart classifier for monitoring alerts (home lab)
In progress

Problem

When a server restarts, monitoring raises an alert and an admin has to check by hand whether the restart was planned or a real problem. Most of the time it was planned, so it's repetitive work.

What I'm building

  • A Windows Server VM on Azure, restarted in different ways: normal restart, Windows Update and forced power-off.
  • A PowerShell script that reads the Windows System event log (IDs 1074, 6008, 41) to find why the server restarted.
  • It classifies each restart as expected or unexpected, the first step toward closing planned-restart alerts automatically and escalating only real incidents.

Azure Site-to-Site VPN for hybrid connectivity

Goal

Connect an on-premise network to Azure securely, so internal resources can reach cloud VMs over private IPs.

Architecture

  • Azure Virtual Network with a dedicated GatewaySubnet.
  • Virtual Network Gateway (route-based) and a Local Network Gateway describing the on-prem side.
  • IPsec/IKE connection with a pre-shared key; on-prem device configured to match.

What I learned

Address-space planning matters: overlapping ranges break routing. Checking the connection status and effective routes is the fastest way to debug.

Servify – E-Services platform

University project · Project leader · Azure DevOps

Online platform where citizens request government services, pay and track their requests. Click to see how it was built.

What it does

  • Three roles: citizens, government offices and admins, each with its own dashboard.
  • Citizens request services, upload documents, book appointments, chat with offices and leave reviews.
  • Requests move through clear statuses (Pending, In Review, Missing Docs, Approved, Rejected, Completed).
  • Each request gets a unique QR code for tracking. Offices are shown on Google Maps.
  • Online payment by card or cryptocurrency, with automatic PDF invoices and certificates.
  • Admin reports: requests per office and revenue.

Architecture

  • Laravel (MVC) backend and responsive Bootstrap frontend.
  • Hosted on Azure App Service, with Azure SQL Database for data and Azure Blob Storage for uploaded documents (MySQL during local development).
  • Laravel Mail and Notifications for emails (OTP codes, status changes, appointment reminders).
  • DomPDF to generate invoices and official documents from templates.

Security

  • Login with email/password or Google (Laravel Socialite).
  • Two-factor authentication with a 6-digit email OTP that expires after 5 minutes.
  • Role-based access checks, so scanning someone else's QR code doesn't reveal their request.

How we worked

  • Tasks planned and tracked in Azure Boards (backlog items assigned, then marked as done).
  • Code in Azure Repos with Git branches and pull requests to merge changes without conflicts.

My role

Project leader: I organized the work in Azure DevOps and developed the platform.
